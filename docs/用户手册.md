# 生产设备点巡检管理系统功能说明书

## 一、系统概述

### 1.1 系统简介

生产设备点巡检管理系统是一套基于失效模式分析（FMEA）的智能化设备点检管理平台。系统通过建立设备点检标准、制定点检计划、生成执行任务、记录执行结果的全流程闭环管理，有效提升设备运行可靠性，降低非计划停机风险。

本系统采用前后端分离架构设计，前端基于 React 18 与 TypeScript 构建，后端采用现代化的 API 接口设计。系统提供直观的数据可视化展示，支持桌面端与移动端自适应访问，满足现场人员多样化的使用场景需求。

### 1.2 系统目标

本系统旨在解决传统点检管理中存在的信息孤岛、执行标准不统一、计划执行率难以追溯等问题。通过标准化的点检流程管理，系统实现了从点检标准制定到任务执行反馈的全程跟踪，确保每台设备的每个关键点检项目都能得到有效执行。

系统的核心价值体现在以下几个方面：首先，通过 FMEA 分析方法论指导点检项目的科学制定，确保点检项的针对性与有效性；其次，建立计划与任务的二级管理机制，支持执行前的条件校验，避免无效点检单据的产生；第三，提供完善的数据统计分析功能，为设备管理决策提供数据支撑；最后，通过移动端适配设计，提升现场人员的操作便捷性。

### 1.3 主要特性

本系统具备以下核心特性：

在标准管理方面，系统支持基于设备类型的多维度标准配置，每个标准可定义多个点检项目，涵盖项目名称、检查方法、执行标准、使用工具等信息，并支持关键项目的特别标注，确保重要点检项得到重点关注。

在计划管理方面，系统实现了计划与任务的解耦设计。计划层面关注何时、对哪台设备、执行哪个标准，任务层面则关注具体执行过程中的状态、结果与问题。这种设计使得计划调整与任务执行相互独立，提升了系统灵活性。

在执行管理方面，系统提供了完善的条件校验机制。在生成任务前，系统会提示当前设备的生产状态、维护状态等信息，由用户判断是否满足点检条件。对于不满足条件的设备，系统支持记录跳过原因，确保每台设备的点检情况都有完整记录。

在数据分析方面，系统提供了多维度的统计报表，包括点检完成率趋势、设备状态分布、跳过原因分析等，帮助管理人员全面掌握点检执行情况。

## 二、功能模块介绍

### 2.1 数据概览模块

数据概览模块是系统的首页与核心数据展示中心，通过直观的卡片式布局与可视化图表，为用户提供设备点检的整体态势感知。

该模块包含四个核心统计指标卡片。设备总数卡片展示系统中录入的设备总量，并通过进度条显示运行中设备占比，帮助用户快速了解设备整体运行状态。已完成点检卡片统计已完成的任务数量，同时通过完成率进度条展示任务执行进度。待处理任务卡片聚焦于待执行的点检任务，当存在待处理任务时显示警示标签，提醒用户及时安排执行。已跳过任务卡片记录因条件不满足而跳过的任务数量，并提示需要跟进未执行原因，确保所有跳过任务都有明确记录。

在图表展示区域，本周点检执行情况以堆叠柱状图的形式，直观展示一周内已完成、进行中、已跳过三类任务的数量分布，便于用户掌握短期内的点检执行节奏。设备状态分布以饼图形式呈现运行中、维护中、停用三类设备的比例，为设备资产配置提供参考依据。

此外，模块还提供了点检标准概览与最近执行记录两个快捷查看区域。点检标准概览展示所有已配置的点检标准，包括标准名称、适用设备类型、包含的项目数量与执行频次。最近执行记录则按时间倒序展示最新的任务执行情况，包括设备名称、执行状态、备注信息与跳过原因，方便用户快速追踪近期点检动态。

### 2.2 设备档案管理模块

设备档案管理模块负责维护企业生产设备的基础信息，是整个点检管理系统的基础数据来源。该模块采用表格化的数据管理方式，支持设备的增删改查操作。

在设备信息维护方面，系统为每台设备建立完整的电子档案，记录设备名称、设备编号、设备类型、所在位置、运行状态等关键信息。设备类型支持数控车床、加工中心、冲压机、注塑机等多种分类，便于后续与点检标准进行关联匹配。设备状态分为运行中、维护中、停用三种，不同状态的设备将影响点检计划的有效性与任务生成逻辑。

模块提供了便捷的设备添加功能，用户通过填写表单即可录入新设备信息。表单包含设备名称、设备编号、设备类型、所在位置、初始状态等必填与选填字段，提交后系统自动生成创建时间与更新时间戳。设备编辑功能支持修改已有设备的基本信息，操作记录会同步更新时间。设备删除功能提供二次确认机制，防止误操作导致的数据丢失。

设备列表支持分页展示，每页默认显示十条记录，提供每页显示条数调节与页码跳转功能。表格列包括设备名称、设备编号、设备类型、位置、状态与创建时间，其中状态列以彩色标签形式区分运行中、维护中、停用三种状态，提升信息识别效率。

### 2.3 点检标准管理模块

点检标准管理模块是系统的核心配置模块，基于 FMEA 方法论设计，支持灵活定义点检项目、检查标准与执行要求。该模块实现了从标准创建、项目配置到执行角色分配的全流程管理。

在标准配置层面，每个点检标准包含标准名称、标准描述、适用设备类型、执行频次与执行角色等属性。标准名称用于标识不同的点检标准，标准描述可详细说明标准的制定依据与注意事项。适用设备类型支持多选配置，允许多种类型的设备共用同一套点检标准，提升标准复用性。执行频次支持每日、每周、每月、每季度四种周期设置，满足不同类型设备的点检需求。执行角色定义了由谁负责执行该标准的点检任务，支持维护技术员、维护主管、操作员三种角色。

在项目配置层面，每个标准可包含多个点检项目，项目是执行任务的最小单元。每个项目包含项目名称、检查标准、检查方法、使用工具、是否关键项等属性。项目名称清晰标识检查内容，检查标准规定合格判定依据，检查方法说明具体检查方式，使用工具记录所需仪器仪表。是否关键项为布尔标识，关键项目在执行界面会有特别提示，确保重要检查项不被遗漏。

模块提供了可视化的标准编辑界面，支持动态添加与删除点检项目。编辑界面采用表单列表设计，每个项目作为一个独立的表单区块，包含所有项目属性。项目顺序可通过删除后重新添加的方式调整，满足实际业务对检查流程的要求。

标准列表采用可展开表格设计，展开后可查看该标准包含的所有点检项目详情，包括每个项目的名称、标准、方法、工具与关键项标识。这种设计使得在列表页面即可快速预览标准的完整内容，无需进入详情页。

### 2.4 点检计划管理模块

点检计划管理模块建立了设备与标准之间的关联关系，是连接设备档案、点检标准与任务执行的关键枢纽。该模块实现了计划的创建、编辑、确认与条件校验功能。

在计划创建方面，用户需要指定计划关联的设备与点检标准，并设定计划执行日期。设备选择从已录入的设备档案中选取，标准选择从已配置的点检标准中选取。计划日期决定了该计划何时进入可执行状态。系统支持为同一台设备创建多个不同标准的点检计划，也支持为同一标准创建多个不同设备的计划，实现灵活的组合配置。

计划状态管理采用五态流转机制：草稿态表示计划刚创建尚未确认，可以进行编辑修改；已确认态表示计划已通过审核，等待条件校验；执行中态表示已通过条件校验，任务已生成；已完成态表示关联任务已执行完毕；已跳过态表示条件校验未通过或执行过程中主动跳过。

模块提供了计划层面的条件校验功能。当计划状态为已确认时，系统提供“执行校验”操作。校验界面展示设备的当前状态信息，包括设备名称、设备状态等核心要素，并提示用户确认设备当前是否满足点检条件。用户可选择“条件满足，生成任务”或“条件不满足，跳过”两个选项。若选择生成任务，计划状态变更为执行中；若选择跳过，系统记录跳过原因，计划状态变更为已跳过。

这种计划与任务解耦的设计理念是本系统的核心创新点。计划阶段关注标准配置与时间安排，不考虑设备当时的实际状态；任务执行阶段才根据设备当前状态决定是否实际执行。对于因生产安排、设备故障等原因暂时无法执行的点检，系统会保留完整的计划记录与跳过原因，为后续的分析改进提供数据支撑。

模块顶部提供了计划统计卡片，包括总计划数、待确认数、执行中数、已完成数四个指标，帮助用户快速掌握计划整体分布情况。

### 2.5 点检任务执行模块

点检任务执行模块是系统的核心操作模块，面向现场执行人员设计。该模块负责展示待执行任务、记录执行结果、管理跳过流程，是闭环管理的最终环节。

任务列表展示了所有点检任务的执行状态与基本信息。列表字段包括设备名称、执行时间、任务状态、跳过原因与备注信息。任务状态分为待执行、执行中、已完成、已跳过四种。待执行状态的任务支持执行与跳过两种操作；已完成与已跳过的任务仅支持查看详情。

任务执行功能提供了结构化的结果录入界面。进入执行页面后，系统根据关联的标准自动加载所有点检项目，每个项目作为一个独立的录入区块。项目区块展示项目名称、检查方法、标准要求与关键项标识，帮助执行人员准确理解检查内容。执行人员需要为每个项目选择检查结果（合格、不合格、不适用），并可选择性填写实测值与备注信息。

关键项标识的项目在执行界面会有特别视觉提示，强调该项目的检查重要性。执行完成后，所有项目结果汇总提交，系统记录完整的执行时间戳与结果数据。

任务跳过功能允许执行人员在特殊情况下跳过点检任务。跳过操作需要填写跳过原因，系统预设了“点检条件不满足”作为常见原因选项，同时支持自定义输入。跳过原因会被完整记录，供后续分析使用。

任务详情查看功能提供了完整的任务信息展示，包括设备信息、执行状态、执行时间、各项检查结果、实测值、备注信息与跳过原因。已完成任务的详情页可作为点检记录存档，支持追溯查询。

### 2.6 统计分析模块

统计分析模块提供了多维度的数据挖掘与可视化展示功能，帮助管理人员全面掌握点检执行情况，为管理决策提供数据支撑。

模块顶部提供了四个核心绩效指标卡片。点检完成率以百分比形式展示已完成任务占总任务的比例，根据完成率水平自动切换颜色显示，达标显示绿色，良好显示橙色，不达标显示红色。已完成任务数与已跳过任务数分别统计两类任务的绝对数量。设备总数展示系统中录入的设备总量。

在时间筛选方面，模块支持按日期范围筛选统计数据，用户可选择特定时间段查看该期间的点检执行情况。设备筛选支持按具体设备查看其点检记录，便于追踪单台设备的点检历史。

图表分析区域包含四个核心图表。点检执行趋势图以折线图形式展示任务完成数与跳过数的时间分布，帮助识别执行规律与异常波动。设备状态分布图以环形饼图展示运行中、维护中、停用设备的占比，为设备资产配置提供参考。点检标准使用情况图以柱状图展示各标准的被调用频次，识别高频使用的标准与潜在优化空间。任务跳过原因分布图以饼图形式分析各类跳过原因的比例分布，为改进措施提供方向。

任务执行记录表格提供了详细的任务流水查询，每条记录包含设备名称、任务状态与执行时间。表格支持分页展示，便于在大数据量场景下快速定位目标记录。

### 2.7 系统设置模块

系统设置模块提供了系统的基本配置与数据管理功能，支持企业个性化定制与数据导入导出操作。

基本设置区域包含企业名称、时区、语言三个配置项。企业名称用于标识系统所属组织机构，会在界面特定位置展示。时区设置影响时间数据的显示格式，系统默认采用中国标准时间（GMT+8）。语言设置预留了多语言支持能力，当前版本支持简体中文，后续可扩展英文等其他语言。

点检配置区域包含自动生成计划、邮件通知、提醒时间三个开关与选项。自动生成计划开关控制是否启用计划自动生成功能，开启后可减少人工干预。邮件通知开关控制是否向相关人员发送任务提醒邮件。提醒时间选项设置提前发送提醒的时间间隔，支持提前一小时、四小时、一天三个档次。

数据管理区域提供了完整的数据导入导出能力。导出功能支持将系统数据导出为 CSV 或 Excel 格式，便于在外部进行数据分析或归档保存。导入功能支持从外部文件批量导入设备、标准等基础数据，提升初始数据录入效率。重置数据功能提供系统数据的一键清空能力，执行前会有二次确认提示，因为该操作不可恢复。

## 三、用户角色说明

### 3.1 设备管理员

设备管理员是系统的核心使用角色，负责设备档案的维护与点检标准的制定。该角色需要深入了解生产设备的结构原理与潜在失效模式，能够基于 FMEA 方法论科学识别关键点检项目。设备管理员通常具备丰富的设备管理经验，能够根据设备运行特点制定合理的点检频次与执行标准。

在日常工作内容方面，设备管理员需要及时录入新采购的设备信息，更新设备的位置变更与状态调整，定期审核设备档案的准确性。在标准管理方面，设备管理员需要根据设备变更、维护经验或故障教训，及时调整点检标准的内容与要求。当发现某类故障频发时，设备管理员需要分析原因并在标准中增加相应的预防性检查项目。

### 3.2 点检执行人员

点检执行人员是点检任务的直接承担者，负责按照计划与标准完成具体的点检执行工作。该角色需要熟悉所负责设备的操作规程与安全要求，能够准确判断设备的运行状态与潜在隐患。点检执行人员可能由现场操作员或维护技术员兼任，根据标准中定义的执行角色确定。

在执行过程中，执行人员需要认真对待每一个点检项目，如实记录检查结果，不得敷衍了事或弄虚作假。对于检查中发现的问题，执行人员需要及时上报并在备注中详细描述异常情况。对于无法立即执行的任务，执行人员需要如实说明原因，确保系统记录的完整性。

### 3.3 管理人员

管理人员主要使用系统的数据统计与分析功能，关注点检工作的整体执行情况与绩效指标。该角色通常不直接参与点检操作，但需要对执行结果负责，需要通过数据反馈持续改进点检管理工作。

管理人员需要定期查看统计分析报表，掌握点检完成率、跳过率等关键指标的变动趋势。对于异常波动需要及时分析原因，采取针对性的改进措施。管理人员还需要关注设备状态分布的变化，评估设备健康水平与维护策略的有效性。

## 四、业务流程说明

### 4.1 标准制定流程

标准制定是点检管理工作的起点，决定了后续所有点检活动的检查内容与判定依据。标准制定流程包括以下关键步骤：

第一步，设备分析。设备管理员识别需要制定点检标准的设备类型，分析该类设备的典型故障模式与潜在失效机理。这一步是 FMEA 分析的核心，需要结合设备说明书、历史故障记录与维护经验进行综合判断。

第二步，项目识别。基于设备分析结果，识别需要纳入点检的关键项目。关键项目应该能够反映设备的核心功能状态，且在故障早期有可观测的异常征兆。项目数量需要平衡全面性与可操作性，避免过多项目导致执行负担过重。

第三步，标准配置。在系统中创建点检标准，填写标准名称与描述信息，选择适用的设备类型，设定执行频次与执行角色。频次设定需要考虑设备重要程度与故障发展速度，关键设备或快速劣化部件应提高检查频次。

第四步，项目配置。为标准添加所有点检项目，填写每个项目的名称、标准、方法、工具等属性。关键项目需要标记为关键项，确保执行时重点关注。项目配置完成后进行审核确认，确保标准内容的完整性与准确性。

### 4.2 计划制定流程

计划制定建立了标准与设备之间的关联关系，确定了点检活动的时间安排与执行对象。计划制定流程包括以下关键步骤：

第一步，设备选择。根据生产安排与设备状态，确定需要纳入点检计划的设备。同一台设备可以根据不同标准创建多个计划，也可以为同一标准创建覆盖多台设备的计划。

第二步，标准关联。为每台待点检设备选择适用的点检标准。标准选择需要考虑设备当前的维护状态与生产计划，避免为处于特殊状态的设备安排不适宜的检查项目。

第三步，时间安排。为每个计划设定具体的执行日期。时间安排需要考虑生产节拍与人员配置，确保执行人员有充足的时间与合适的机会完成点检工作。

第四步，计划确认。计划创建完成后进入待确认状态，由具备审核权限的人员确认计划的合理性。确认通过后计划状态变更为已确认，等待进入条件校验环节。

### 4.3 任务执行流程

任务执行是点检管理的核心环节，直接决定了点检工作的实际效果。任务执行流程包括以下关键步骤：

第一步，条件校验。在生成任务前，执行人员需要判断设备当前是否满足点检条件。系统会展示设备的基本信息与当前状态，执行人员根据实际情况选择条件满足或条件不满足。若选择条件满足，系统生成具体的执行任务；若选择条件不满足，系统记录跳过原因，任务标记为已跳过。

第二步，结果录入。执行人员按照标准要求逐项检查设备状态，准确选择每项的检查结果。合格项目标记为合格，不合格项目标记为不合格并进行详细描述，因客观原因无法检查的项目标记为不适用。每项检查可选择性记录实测值与备注信息。

第三步，结果提交。完成所有项目的检查后，提交执行结果。系统记录完整的提交时间戳，并将任务状态变更为已完成。对于检查中发现的不合格项，系统支持后续跟踪处理流程。

### 4.4 闭环追溯流程

闭环追溯是确保点检管理持续改进的重要机制。通过建立计划、任务、结果的完整记录链条，系统支持多种追溯查询场景：

按设备追溯可以查看某台设备的所有点检计划与执行记录，分析该设备的点检历史与问题趋势。按标准追溯可以查看某套标准的应用范围与执行情况，评估标准的覆盖性与有效性。按时间追溯可以查看特定时间段内的所有点检活动，支撑周期性工作总结与考核。按原因追溯可以查看所有跳过任务的跳过原因分布，识别系统性的执行障碍并针对性改进。

## 五、界面操作指南

### 5.1 导航操作

系统采用左侧菜单导航设计，桌面端显示完整的菜单标签与图标，移动端自动切换为汉堡菜单与底部标签栏。菜单项按功能模块分组，依次为数据概览、设备档案、点检标准、点检计划、任务执行、统计分析、系统设置。点击菜单项即可切换到对应模块，当前模块在菜单中以高亮方式标识。

桌面端菜单支持折叠功能，点击侧边栏底部的折叠按钮可将菜单收起，仅显示图标。折叠状态适合在需要更大内容显示区域时使用。移动端菜单通过顶部导航栏的汉堡按钮触发，点击后从左侧滑出导航抽屉，底部标签栏提供常用模块的快捷入口。

### 5.2 列表操作

各管理模块采用统一的列表展示界面，操作方式保持一致性。列表支持分页展示，默认每页显示十条记录，可通过分页控件切换页码或调整每页条数。表格列支持排序功能，点击列标题可按该列升序或降序排列。

列表提供筛选与搜索功能，可在列表上方通过表单控件筛选显示范围。高级筛选支持多条件组合，快速定位目标记录。表格每行末尾提供操作按钮区域，常见的操作包括查看详情、编辑修改、删除确认等。

### 5.3 表单操作

新增与编辑操作采用模态框表单实现。点击新增按钮后弹出表单模态框，填写完成后点击确认提交。编辑操作触发的表单模态框会预填充已有数据，修改后提交更新。表单提交前会进行必填项校验，未填写的必填项会以红色提示标识。

表单支持动态列表字段，以点检项目的配置为例。在项目配置表单中，可以点击添加按钮新增一个项目区块，每个区块包含项目的各项属性。也可以点击删除按钮移除不需要的项目。这种动态配置方式灵活适应了不同标准的项目数量差异。

### 5.4 确认操作

涉及数据修改的操作会弹出确认提示，防止误操作导致的数据损失。确认提示包含操作说明与影响范围说明，用户需要明确了解后果后点击确认执行或取消放弃。对于删除操作，系统采用二次确认机制，需要在首次确认后再进行一次确认才能完成删除。

## 六、数据安全说明

### 6.1 数据存储

系统采用前端本地存储的方式管理数据，所有业务数据保存在浏览器本地存储中。这种设计适合小规模团队使用场景，部署简便且无服务器依赖。数据存储包括设备档案、点检标准、点检计划、任务执行记录等完整业务数据。

需要注意的是，本地存储的数据与浏览器绑定，更换浏览器或清除缓存会导致数据丢失。建议定期使用系统的导出功能备份重要数据，导出的格式支持 CSV 与 Excel，便于在外部进行长期归档。

### 6.2 数据导入导出

系统提供了完善的数据导入导出功能，支持基础数据的批量维护。导出功能可将当前数据导出为结构化文件，导出的内容涵盖设备档案、点检标准等核心数据。导入功能支持从外部文件批量录入数据，减少手工录入的工作量。

数据导入前需要按系统要求的格式准备文件，确保字段对应关系正确。导入过程会进行数据校验，对于格式错误的记录会提示修正。导入操作不会覆盖已有数据，对于重复记录需要先清理已有数据或修改导入策略。

## 七、系统维护说明

### 7.1 数据备份

虽然系统采用本地存储设计，但提供了便利的数据导出功能支持备份需求。建议用户定期导出系统数据，将导出的文件保存在安全的位置。在进行系统升级或浏览器重大更新前，建议进行一次完整的数据导出备份。

### 7.2 数据重置

系统提供了数据重置功能，可以一键清除所有业务数据。该功能主要用于系统初始化或测试场景。执行数据重置前，系统会进行二次确认提醒，明确告知该操作不可恢复。重置操作会清除设备档案、点检标准、点检计划与任务执行记录，请谨慎使用。

### 7.3 版本更新

系统基于 React 技术栈构建，支持热更新机制。当系统有新版本发布时，刷新浏览器页面即可获取最新功能。更新过程不会影响已存储的数据，业务数据在本地存储中保持持久化。

## 八、技术规格说明

### 8.1 技术架构

系统采用前后端分离的现代 Web 应用架构，前端基于 React 18 框架开发，使用 TypeScript 进行类型安全编程。构建工具采用 Vite，提供快速的开发体验与优化的生产构建。UI 组件库使用 Ant Design 5，保证界面的专业性与一致性。状态管理采用 Zustand，路由管理使用 React Router DOM 6。

### 8.2 响应式设计

系统采用移动优先的响应式设计理念，界面能够自动适应从手机到桌面显示器的各种屏幕尺寸。桌面端展示完整的侧边导航与数据表格，移动端自动切换为折叠菜单与卡片布局。响应式断点设在 768 像素，小于该宽度触发移动端布局模式。

### 8.3 浏览器兼容

系统支持主流的现代浏览器，包括 Chrome、Firefox、Safari、Edge 的最新版本。浏览器需要启用 JavaScript 支持，并允许本地存储访问。建议使用 Chrome 浏览器以获得最佳使用体验。
