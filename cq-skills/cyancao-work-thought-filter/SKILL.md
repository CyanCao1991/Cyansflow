# Cyan的工作思考过滤器

## 定位

嵌入日常工作流的"前置过滤器"。在你动手做事之前，先判断"这件事该不该做、做到什么程度、该不该是我做"。

## 触发时机

**任何需要"动手做事"之前**——包括但不限于：
- 接到新需求或任务
- 准备优化现有流程
- 要写方案、做PPT、填报表
- 开会前准备材料
- 想自动化某个环节
- 用户说"帮我排优先级"、"这个需求怎么看"、"这个该不该做"

触发方式：用户说出"我要开始做XX"或"帮我做XX"时，**先不执行，跑一遍这个Skill**。

## 执行流程（分步互动模式）

> ⚠️ **核心规则：每一步执行后，必须与用户互动，等待用户确认后再决定下一步。**
>
> 用户可选择：**"继续下一步" / "完成（跳过后续步骤）" / "回退修改当前步骤"**

---

### 第0步：黄金圈启动（必须执行）

在质疑需求之前，先花2分钟过黄金圈——**思考2分钟 > 无意义行动2小时**。

**WHY——三秒思考**
- 我为什么要做？
- 没有外力的情况下我还会做吗？
- 答案是否定的，立即标记并反馈

**HOW——原则与路径**
- 为了WHY，必须遵循什么原则？
- 用什么流程或方法？
- 行动方式是否服务于WHY？

**WHAT——最小可行验证**
- 是否有立即可行动项？
- 最小可行性行动是什么？
- 行动是否遵循HOW、服务WHY？

**授权判断**
- 基于WHY，是否必须我做？可以别人做的就不要自己做。授人以渔。
- 基于WHY，是否必须现在做？工作除突发事件外必须按计划做事，计划可调整但必须按计划时间安排。

**输出物：** 一条判断——"做 / 暂缓 / 砍掉 / 转交"，附理由。

**关键提醒：** WHY为"否"不等于砍掉。属于"重要但不紧急"的长期投资，标记为"暂缓"。暂缓的事定期回顾，砍掉的事不再回来。

**🔄 执行后互动：** 向用户展示判断结果，等待用户确认。用户可选择：
- "继续" → 进入第1步
- "完成" → 结束本次过滤器，按判断结果执行
- "调整" → 根据用户反馈修正判断

---

### 第1步：质疑需求

**前提：** 第0步判断为"做"之后才进入。

追问三组问题：
1. 这个需求是谁提的？找到提出需求的具体人
2. 他为什么这样提？背后的理由是什么？
3. 什么情况下这个理由不成立？

**输出物：** 一条判断——"应该做 / 应该改 / 应该砍"，附理由。

**关键提醒：** 聪明人提的需求最危险——权威性导致无人质疑，但逻辑可能早已过时。找不到提需求的人，或答不出"什么情况下理由不成立"，这个需求大概率该砍。

**🔄 执行后互动：** 向用户展示判断结果，等待用户确认。用户可选择：
- "继续" → 进入第2步
- "完成" → 结束本次过滤器，按当前判断执行
- "回退" → 回到第0步重新思考

---

### 第2步：尽量删减

列出当前方案中所有环节/步骤/字段，逐条追问：
- 这一步是"一直这样"还是"验证过必须这样"？
- 删掉后会怎样？
- 少于10%的情况需要加回来，说明删得还不够

**输出物：** 删减清单——"保留 / 可删 / 待验证"，附理由。

**关键提醒：** 真正的删减是有点过头的，是那种让你轻微不安的程度。删完感觉"一切刚刚好"，说明还没开始删。

**🔄 执行后互动：** 向用户展示删减清单，等待用户确认。用户可选择：
- "继续" → 进入第3步
- "完成" → 结束本次过滤器，按删减后的方案执行
- "回退" → 回到第1步重新质疑

---

### 第3步：简化和优化

**前提：** 前两步通过后才进入。

在删减后的基础上，重新设计最短路径：
- 不是在原有结构上打补丁，而是从"最少环节"出发，只加回必要的部分
- 重新排列顺序，砍掉所有"为了流程而流程"的步骤
- **每个环节必须能回答"这服务了第0步的WHY吗？"——服务不了的，再简洁也是多余**

**输出物：** 简化后的方案骨架，与原方案对比，标注差异。

**🔄 执行后互动：** 向用户展示简化方案，等待用户确认。用户可选择：
- "继续" → 进入第4步
- "完成" → 结束本次过滤器，按简化方案执行
- "回退" → 回到第2步重新删减

---

### 第4步：加速执行

**前提：** 确认方向对了再提速。前三步没过，这一步就是"挖坟墓挖更快"。

先用第0步的WHAT找到最小可行行动项，再在确认该做的事上：
- 找出执行链路中的瓶颈
- 用并行替代串行
- 用模板替代临时
- 用AI替代重复手工

**输出物：** 加速方案，标注预期效率提升。**从最小可行行动项开始，而非一步到位。**

**🔄 执行后互动：** 向用户展示加速方案，等待用户确认。用户可选择：
- "继续" → 进入第5步
- "完成" → 结束本次过滤器，按加速方案执行
- "回退" → 回到第3步重新简化

---

### 第5步：自动化

**前提：** 只自动化"确认该存在的流程"。

对确认需要反复执行的环节：
- 判断是否值得投入自动化成本（频率 × 节省时间 vs 开发成本）
- 选择自动化方式：规则引擎 / 脚本 / AI Agent / 工具集成
- 保留人工兜底机制

**输出物：** 自动化方案，包含工具选型、开发成本估算、兜底策略。

**🔄 执行后互动：** 向用户展示自动化方案，等待用户确认。用户可选择：
- "完成" → 结束本次过滤器，按自动化方案执行
- "回退" → 回到第4步重新思考加速策略

---

## 反面检查清单

每次执行前，快速自检：
1. 我是不是跳过了第0步，在做一件"没有WHY"的事？
2. 我是不是跳过了第1步，直接在优化一个可能不该存在的东西？
3. 我是不是在"添加"而不是"删减"？（添加的认知负担更低，但往往是错的方向）
4. 如果我正在挖坟墓，我是不是在挖得更快？

## 使用示例

**场景：接到"优化报表流程"的需求**

❌ 常规路径：直接看现有报表怎么做得更快

✅ 五步法路径（分步互动）：
1. 第0步→输出"暂缓/转交"→用户确认"继续"→
2. 第1步→输出"应该砍"→用户确认"完成"→结束
